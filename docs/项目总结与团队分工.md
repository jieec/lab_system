# 项目总结与团队分工说明

## 一、项目概况

| 项目 | 内容 |
|------|------|
| 项目名称 | 高校实验室预约与设备运维系统 |
| 项目类型 | 课程设计 / 团队协作项目 |
| 团队规模 | 5 人 |
| 技术栈 | Vue 3 + Vite + Element Plus + Pinia / Spring Boot 3 + MyBatis-Plus + MySQL 8 |
| 系统角色 | 学生、教师、管理员、维修员 |
| 数据库 | 12 张表 |
| 业务模块 | 13 个（认证、用户、实验室、设备、预约、闭馆、报修、信用、通知、站内信、日志、统计、AI 助手） |
| 测试用例 | 70+ 个（JUnit 5） |

## 二、解决的问题

高校实验室管理长期依赖纸质登记或微信群接龙，存在四个突出问题：

| 痛点 | 具体表现 | 本系统的解法 |
|------|----------|--------------|
| 预约冲突 | 群里接龙，没人知道时段是否已被占用 | 时段时间轴可视化 + 后端冲突判定 + 行锁保证并发正确 |
| 到场率低 | 约了不来，资源空置，也没人追责 | 签到机制 + 信用分扣分 + 低于门槛禁止预约 |
| 报修无跟踪 | 设备坏了在群里说一声，修没修、谁在修不清楚 | 工单闭环 + 派单 + 全程流转日志 + 验收评分 |
| 数据难统计 | 用了多少次、坏了几台，全靠人工回忆 | 首页看板 + 审计日志 + 结构化数据可导出 |

## 三、团队分工

分工原则：**按业务域纵向切分**，每人负责从数据库到接口到页面的完整一条线，避免前后端互相等待；公共基础部分由两人牵头定规范，其他人遵循。

### 成员 A — 认证与权限体系

| 项目 | 内容 |
|------|------|
| 负责模块 | 登录认证、用户管理 |
| 后端产出 | `AuthController`、`UserController`、`AuthService`、`UserService`、`JwtUtil`、`JwtFilter`、`UserContext`、`@RequireRole` 注解与拦截器 |
| 核心工作 | JWT 签发与解析、令牌版本号主动失效机制、BCrypt 密码加密、用户增删改查、重置密码、账号启停、角色权限校验 |
| 技术难点 | JWT 无法主动注销 → 引入 `token_version` 字段与 `ver` 声明比对 |
| 测试 | `JwtUtilTest`（签发/解析/版本/密钥/过期/篡改） |
| 前端页面 | 登录页、个人中心、用户管理页 |

### 成员 B — 资源台账

## 五、项目亮点

### 1. 并发安全的预约（技术亮点）

不是「查一下没冲突就插入」，而是事务第一条语句就 `SELECT ... FOR UPDATE` 锁实验室行，把同一实验室的写操作串行化。等待锁的事务拿到锁之后才建立读视图，因此能看到前一个事务已提交的预约，从根本上消除竞态。

### 2. 可执行的信用治理（业务亮点）

把「爽约」从道德约束变成系统约束：扣分、门槛、近期次数限制、申诉恢复、恢复上限，形成闭环。所有变动有流水、可追溯、可申诉，比人工封号更公平。

### 3. AI 助手真正能办事（创新亮点）

不是套壳聊天机器人。通过 Function Calling 调用真实业务接口，能查实验室、查时段、提交预约。同时用「确认卡片」机制解决 AI 误操作风险——写操作必须用户点确认才执行。

### 4. 规则集中、可测试（工程亮点）

`TimeWindow`、`ReservationState`、`CreditPolicy` 三个规则类不依赖数据库和 Spring 容器，规则只写一遍，测试可以直接 new 出来断言。70+ 测试用例里有 30 多个是直接测这三个类的。

### 5. 全链路留痕（管理亮点）

`@OperationLog` 注解 + AOP 切面自动记录敏感操作，报修工单每次流转写 `repair_log`，信用每次变动写 `credit_record`。出了问题能定位到人、时间、参数。

## 六、项目不足与改进方向

| 不足 | 现状 | 改进方向 |
|------|------|----------|
| 无实时推送 | 站内信用轮询未读数 | 接 WebSocket 或 SSE 做实时通知 |
| token 校验查库 | 每次请求查一次 `sys_user` | 版本号缓存到 Redis |
| 预约锁为单库行锁 | 单机 MySQL 行锁 | 高并发场景换 Redis 分布式锁 |
| 无文件上传 | 设备图片、故障照片未支持 | 接对象存储（OSS/MinIO） |
| 报表能力弱 | 看板只有汇总数字 | 加趋势图、导出 Excel、按学院统计 |
| 移动端未适配 | 仅桌面端布局 | 响应式改造或做小程序 |
| 无国际化 | 中文硬编码 | 抽 i18n 资源文件 |

## 八、总结

本项目在一个课程周期内完成了一套覆盖「预约—使用—报修—信用」完整闭环的实验室管理系统，包含 13 个业务模块、12 张数据表、70 多个测试用例。

技术上，重点解决了预约并发冲突、JWT 主动失效、工单状态闭环三个有实际难度的问题，并把核心业务规则抽成可独立测试的规则类。

业务上，信用分机制把「爽约」这个长期无解的管理难题变成了系统可执行的约束；AI 助手让自然语言操作真实业务成为可能，同时用确认卡片守住安全边界。

团队上，按业务域纵向分工让五个人能并行推进，公共规范由专人牵头保证一致性。
