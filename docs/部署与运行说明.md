# 部署与运行说明

> 适用环境：Windows 10/11、macOS、Linux
> 依赖：JDK 21、Maven 3.8+、Node.js 18+、MySQL 8.0
> 快速启动：双击项目根目录 `启动系统.bat`（Windows）

---

## 一、环境要求

| 组件 | 版本要求 | 检查命令 |
|------|----------|----------|
| JDK | 21 及以上 | `java -version` |
| Maven | 3.8 及以上 | `mvn -v` |
| Node.js | 18 及以上 | `node -v` |
| npm | 9 及以上 | `npm -v` |
| MySQL | 8.0 及以上 | `mysql --version` |

> 后端使用 Java 21 的 `switch` 表达式和 `Math.clamp`，**JDK 17 无法编译**，务必确认版本。

## 二、数据库准备

### 2.1 建库建表

```bash
# schema.sql 已包含 CREATE DATABASE 与 USE，无需手动建库
mysql -uroot -p < lab-backend/src/main/resources/sql/schema.sql
```

### 2.2 导入演示数据

```bash
mysql -uroot -p lab_system < lab-backend/src/main/resources/sql/data.sql
```

### 2.3 验证

```bash
mysql -uroot -p -e "use lab_system; show tables; select username, role from sys_user;"
```

应看到 12 张表，以及 `admin` / `t_wang` / `s2021001` / `r_zhang` 等账号。

> 如果之前已导入过旧版本，可执行 `migrate.sql` 做增量升级，不要直接 drop 库。

## 三、配置说明

后端读取 `application.yml`，敏感配置通过环境变量覆盖，不写死在代码里。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `MYSQL_HOST` | `localhost` | 数据库地址 |
| `MYSQL_PORT` | `3306` | 数据库端口 |
| `MYSQL_USERNAME` | `root` | 数据库账号 |
| `MYSQL_PASSWORD` | `123456` | 数据库密码，**本机运行时必须改成真实密码** |
| `JWT_SECRET` | 内置演示值 | JWT 签名密钥，**公开展示时务必改成随机长字符串** |
| `LLM_ENABLED` | `true` | 是否启用 AI 助手 |
| `LLM_BASE_URL` | `https://api.deepseek.com` | LLM 服务地址 |
| `LLM_MODEL` | `deepseek-flash` | 模型名 |
| `LLM_API_KEY` | 空 | LLM 密钥，留空则走规则演示模式 |

### 3.1 用环境变量传密码（推荐）

Windows CMD：

```bat
set MYSQL_PASSWORD=你的密码
cd lab-backend
mvn spring-boot:run
```

Windows PowerShell：

```powershell
$env:MYSQL_PASSWORD="你的密码"
cd lab-backend
mvn spring-boot:run
```

macOS / Linux：

```bash
export MYSQL_PASSWORD='你的密码'
cd lab-backend && mvn spring-boot:run
```

### 3.2 用 .env 文件

项目根目录支持 `.env`（已被 `.gitignore` 忽略，不会提交到仓库）：

```bash
cp .env.example .env
# 编辑 .env，填入真实密码
```

## 四、启动方式

### 4.1 一键启动（Windows，推荐答辩现场使用）

双击项目根目录的 **`启动系统.bat`**，脚本会依次：

1. 检查环境
2. 启动后端（8080）
3. 等待 15 秒
4. 启动前端（5173）
5. 自动打开浏览器

### 4.2 手动启动（开发调试）

**终端 1 — 后端**

```bash
cd lab-backend
mvn spring-boot:run
```

看到 `Started LabApplication in x.x seconds` 即为成功。

**终端 2 — 前端**

```bash
cd lab-frontend
npm install     # 首次运行需要，约 1–3 分钟
npm run dev
```

访问 `http://localhost:5173`。

### 4.3 打包成 jar 运行

```bash
cd lab-backend
mvn clean package -DskipTests
java -jar target/lab-backend.jar --server.port=8080
```

前端打包：

```bash
cd lab-frontend
npm run build
# 产物在 dist/，可交给 Nginx 托管
```

### 4.4 Docker Compose（一键起全套）

```bash
cp .env.example .env
# 编辑 .env，设置 MYSQL_PASSWORD 与 JWT_SECRET
docker compose up -d
```

| 服务 | 地址 |
|------|------|
| 前端 | `http://localhost:8081` |
| 后端 | `http://localhost:8080` |
| MySQL | `localhost:3307`（宿主机映射端口） |

停止：`docker compose down`；连数据一起删：`docker compose down -v`。

## 七、常见故障排查

### 7.1 后端启动失败

| 报错 | 原因 | 解决 |
|------|------|------|
| `Access denied for user 'root'@'localhost'` | 数据库密码不对 | 设置 `MYSQL_PASSWORD` 环境变量为真实密码 |
| `Unknown database 'lab_system'` | 未执行建表脚本 | 执行 `schema.sql` |
| `Communications link failure` | MySQL 未启动 | 启动 MySQL 服务 |
| `Table 'lab_system.xxx' doesn't exist` | 表缺失或版本旧 | 重新执行 `schema.sql`，或跑 `migrate.sql` |
| `Port 8080 was already in use` | 端口被占用 | 见 7.3 |
| `invalid target release: 21` | JDK 版本过低 | 安装 JDK 21 并配置 `JAVA_HOME` |

### 7.2 前端问题

| 现象 | 原因 | 解决 |
|------|------|------|
| `npm install` 报错 | Node 版本过低或网络问题 | 升级 Node 18+，或换国内镜像 `npm config set registry https://registry.npmmirror.com` |
| 页面能开但接口 404 | 后端未启动 | 启动后端，确认 8080 可访问 |
| 接口 401 | token 过期或已失效 | 重新登录 |
| 白屏且控制台报模块错误 | 依赖未装全 | 删 `node_modules` 重装 |
| 样式错乱 | 浏览器缓存 | `Ctrl + F5` 强制刷新 |

### 7.3 端口被占用

**Windows 查占用进程**

```bat
netstat -ano | findstr :8080
taskkill /PID <进程号> /F
```

**macOS / Linux**

```bash
lsof -i :8080
kill -9 <PID>
```

**换端口启动**

```bash
# 后端
java -jar target/lab-backend.jar --server.port=8081
# 或
mvn spring-boot:run -Dspring-boot.run.arguments=--server.port=8081
```

前端换端口时需同步修改 `lab-frontend/vite.config.js` 里的代理 `target`：

```bash
npm run dev -- --port 5174
```

### 7.4 AI 助手不工作

| 现象 | 原因 | 解决 |
|------|------|------|
| 助手只回固定话术 | 未配置 `LLM_API_KEY`，走规则模式 | 配置 Key 后重启后端 |
| 助手报超时 | 网络不通或 Key 无效 | 检查 `LLM_BASE_URL` 与 Key；无网络时用规则模式演示 |
| 确认卡片不弹出 | 该操作被判定为读操作 | 只有写操作才需要确认，属正常 |

### 7.5 数据被改乱，想恢复演示状态

```bash
mysql -uroot -p < lab-backend/src/main/resources/sql/schema.sql
mysql -uroot -p lab_system < lab-backend/src/main/resources/sql/data.sql
```

> `schema.sql` 开头有 `DROP TABLE IF EXISTS`，执行会清空所有数据，**仅用于演示环境**。
