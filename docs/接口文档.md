# 高校实验室预约与设备运维系统 — 接口文档

> Base URL: `/api`
> 认证方式: Bearer Token（JWT），请求头 `Authorization: Bearer <token>`
> 统一响应结构: `{ "code": 200, "msg": "操作成功", "data": ... }`
> 分页响应结构: `{ "code": 200, "msg": "操作成功", "data": { "total": 100, "records": [...] } }`

---

## 0. 通用说明

### 0.1 角色标识

| 角色 | code |
|------|------|
| 管理员 | ADMIN |
| 教师 | TEACHER |
| 学生 | STUDENT |
| 维修员 | REPAIRER |

### 0.2 状态码

| code | 含义 |
|------|------|
| 200 | 成功 |
| 401 | 未登录或 token 失效 |
| 403 | 无权限 |
| 500 | 业务异常或服务器错误 |

### 0.3 团队分工说明

本接口文档按五个成员负责的模块进行组织，每位成员负责一组完整的接口：

| 成员 | 模块 | 接口数量 |
|------|------|----------|
| 成员 A | 登录认证（Auth）+ 用户管理（User） | 12 个 |
| 成员 B | 实验室管理（Lab）+ 设备台账（Equipment） | 16 个 |
| 成员 C | 实验室预约（Reservation）+ 闭馆安排（Closure） | 13 个 |
| 成员 D | 报修运维（Repair）+ 信用管理（Credit） | 15 个 |
| 成员 E | 通知公告（Notice）+ 站内信（Message）+ 审计日志（Log）+ 统计看板（Stats）+ AI 助手（Agent） | 15 个 |


## 5. 实验室预约模块（成员 C 负责）

### 5.1 提交预约申请

```
POST /api/reservations
```

**权限**: 已登录（信用分 >= 60）

**请求体**:
```json
{
  "labId": 1,
  "startTime": "2026-11-20T14:00:00",
  "endTime": "2026-11-20T16:00:00",
  "headcount": 5,
  "purpose": "课程实验",
  "remark": "需要使用示波器"
}
```

**校验**:
- labId 不能为空
- startTime / endTime 不能为空
- headcount >= 1
- 信用分低于 60 禁止预约
- 时段不能与已有预约冲突
- 闭馆日期不可预约

**响应**:
```json
{
  "code": 200,
  "msg": "提交成功，等待审批",
  "data": {
    "id": 10,
    "orderNo": "RES-202611200001",
    "status": "PENDING",
    "checkinStatus": "NONE"
  }
}
```

> 如果实验室 `needApproval=0`，则直接 APPROVED，msg 为 "预约成功"。

### 5.2 我的预约

```
GET /api/reservations/my?pageNum=1&pageSize=10&status=PENDING
```

**权限**: 已登录

### 5.3 预约审批列表

```
GET /api/reservations?pageNum=1&pageSize=10&status=PENDING&labId=1&keyword=张&date=2026-11-20
```

**权限**: ADMIN / TEACHER

**查询参数**:

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| pageNum | int | 否 | 1 | 页码 |
| pageSize | int | 否 | 10 | 每页条数 |
| status | string | 否 | - | 状态（PENDING/APPROVED/REJECTED/CANCELLED/FINISHED） |
| labId | long | 否 | - | 实验室 ID |
| keyword | string | 否 | - | 预约人姓名/学号关键词 |
| date | string | 否 | - | 日期筛选 |

### 5.4 时段查询

```
GET /api/reservations/timeline?labId=1&date=2026-11-20
```

**权限**: 已登录

**说明**: 返回某实验室某天已预约的时段列表，前端据此展示时间轴

### 5.5 预约详情

```
GET /api/reservations/{id}
```

### 5.6 审批预约

```
PUT /api/reservations/{id}/approve
```

**权限**: ADMIN / TEACHER

**请求体**:
```json
{
  "pass": true,
  "remark": "同意"
}
```

> pass=false 时填写驳回原因

### 5.7 取消预约

```
PUT /api/reservations/{id}/cancel
```

**权限**: 预约人本人

### 5.8 预约签到

```
PUT /api/reservations/{id}/checkin
```

**权限**: 预约人本人

**说明**: 仅在预约时段内可签到，签到后 checkinStatus 变为 CHECKED_IN。超时未签到记为 NO_SHOW，扣减信用分。

### 5.9 申请改期

**权限**: 预约人本人

## 附录 A. 枚举值汇总

### 预约状态 (Reservation.status)
| 值 | 说明 |
|----|------|
| PENDING | 待审批 |
| APPROVED | 已通过 |
| REJECTED | 已驳回 |
| CANCELLED | 已取消 |
| FINISHED | 已完成 |

### 签到状态 (Reservation.checkinStatus)
| 值 | 说明 |
|----|------|
| NONE | 未签到 |
| CHECKED_IN | 已签到 |
| NO_SHOW | 爽约 |

### 设备状态 (Equipment.status)
| 值 | 说明 |
|----|------|
| IDLE | 空闲 |
| IN_USE | 使用中 |
| REPAIR | 维修中 |
| SCRAPPED | 已报废 |

### 工单状态 (RepairOrder.status)
| 值 | 说明 |
|----|------|
| PENDING | 待派单 |
| ASSIGNED | 已派单 |
| REPAIRING | 维修中 |
| DONE | 待验收 |
| VERIFIED | 已完成 |

### 工单流转动作 (RepairLog.action)
| 值 | 说明 |
|----|------|
| CREATE | 创建工单 |
| ASSIGN | 派单 |
| START | 开始维修 |
| FINISH | 完成维修 |
| VERIFY | 验收 |

### 紧急程度 (RepairOrder.urgency)
| 值 | 说明 |
|----|------|
| LOW | 低 |
| NORMAL | 普通 |
| HIGH | 紧急 |

### 公告类型 (Notice.type)
| 值 | 说明 |
|----|------|

| MAINTENANCE | 维护 |

| 值 | 说明 |
