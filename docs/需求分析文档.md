# 高校实验室预约与设备运维系统 — 需求分析文档

## 1. 项目概述

### 1.1 项目背景

高校实验室是教学和科研的重要场所，日常面临预约冲突、设备损坏报修流程不透明、使用人员信用难以追踪等问题。传统纸质或微信群预约方式效率低下、数据难以统计，亟需一套信息化系统实现实验室资源的统一管理和高效流转。

### 1.2 项目目标

构建一个覆盖**实验室预约、设备台账、报修运维、信用管理、通知公告**五大核心业务的一体化管理系统，支持学生、教师、管理员、维修员四种角色，并提供 AI 智能助手辅助日常操作。

### 1.3 技术栈

| 层次 | 技术选型 |
|------|----------|
| 前端 | Vue 3 + Vite + Element Plus + Pinia |
| 后端 | Spring Boot 3 + MyBatis-Plus + MySQL 8 |
| 认证 | JWT（自实现，token 版本号机制支持即时失效） |
| 接口文档 | Swagger / OpenAPI 3（springdoc-openapi） |
| AI 助手 | SSE 流式对话 + Function Calling 业务工具 |
| 部署 | Docker Compose / 本地脚本启动 |

## 4. 非功能需求

### 4.1 安全性

- 密码使用 BCrypt 加密存储
- JWT token 携带 token 版本号，修改密码/停用账号时版本号自增，旧 token 立即失效
- 接口级角色权限控制（`@RequireRole`）
- 敏感操作自动记录审计日志（`@OperationLog`）
- 密码字段使用 `@JsonIgnore` 不返回给前端

### 4.2 性能

- 分页查询统一使用 MyBatis-Plus 分页插件
- 实验室列表等高频查询接口支持不分页返回
- 前端使用 Vite 构建优化加载性能

### 4.3 可用性

- 统一响应结构 `R<T>`，前端可统一处理错误
- 表单校验使用 Jakarta Validation 注解
- 友好的中文错误提示

### 4.4 可维护性

- 前后端分离，职责清晰
- 接口文档使用 OpenAPI 3 注解自动生成
- 代码分层：Controller → Service → Mapper → Entity

## 6. 团队分工

本项目由五名成员协作完成，按照模块进行分工：

| 成员 | 负责模块 | 主要职责 |
|------|----------|----------|
| 成员 A | 登录认证 + 用户管理 | JWT 认证体系、用户增删改查、权限注解、密码安全 |
| 成员 B | 实验室管理 + 设备台账 | 实验室 CRUD、设备 CRUD、状态管理、楼栋筛选 |
| 成员 C | 实验室预约 + 闭馆安排 | 预约全流程（提交/审批/签到/改期/取消）、时段冲突检测、闭馆管理 |
| 成员 D | 报修运维 + 信用管理 | 报修工单闭环（提交/派单/维修/验收）、信用分变动与恢复 |
| 成员 E | 通知公告 + 站内信 + 审计日志 + 统计看板 + AI 助手 | 公告管理、消息推送、操作留痕、首页看板、AI 对话集成 |

## 7. 约束与假设

1. 系统面向单校区使用，不考虑多校区场景
2. 预约时间粒度为小时级
3. 信用分初始 100 分，低于 60 分禁止预约
4. 报修工单必须关联设备
5. 管理员可操作所有模块，不受角色限制
